# M3A DHT11采集设计

## 1. 目标与范围

M3A在现有STM32F407VET6、FreeRTOS、USART1和ST7735S基础工程中接入三针DHT11模块，实现周期采集、校验、错误报告和断线自动恢复。

本阶段只处理DHT11。MQ-2继续保持未连接，直到具备万用表、10 kΩ与15 kΩ分压电阻和面包板。DHT11数据只通过USART1输出，不修改当前ST7735S自检画面；正式传感器界面与LVGL移植留到M9。

## 2. 已确认约束

- DHT11为三针模块，使用3.3V供电，使数据上拉电平保持在STM32 IO安全范围内。
- DHT11 DATA使用PD0。
- TIM5专用于DHT11微秒计时；TIM6继续作为HAL时基，SysTick继续作为FreeRTOS时基。
- DHT11每2秒读取一次，避免超过器件允许的刷新频率。
- 断线时读取必须有界返回，不能卡死任务。
- 重新接入传感器后，无需复位即可在后续采样周期自动恢复。
- PA0、PA1、USART1心跳和ST7735S现有功能必须保持正常。

## 3. 方案选择

### 3.1 微秒计时

采用TIM5的32位自由运行计数器：

```text
计数频率：1 MHz
每个计数：1 μs
计数模式：向上计数
自动重装值：0xFFFFFFFF
中断：关闭
```

未采用DWT CYCCNT，因为它依赖内核周期计数器初始化和168 MHz时钟换算，调试与移植不如1 MHz定时器直观。未采用EXTI或输入捕获，因为DHT11每2秒才读取一次，引入边沿状态机与中断处理不符合当前最小实现目标。

所有时间差均使用无符号计数器相减，使TIM5溢出时仍能正确计算短时间间隔。

### 3.2 任务组织

新建独立`SensorTask`，不继续扩大`App_DefaultTask`。任务初始配置为：

```text
任务名：sensorTask
入口：StartSensorTask
优先级：Normal
栈大小：256 Words
分配方式：Dynamic
周期：2000 ms
```

`App_DefaultTask`继续承担当前M1/M2演示功能：启动时执行ST7735S自检，随后每秒翻转PA1、读取PA0并输出心跳。M3A不建立完整`SystemState`和传感器互斥量；这些结构在MQ-2或控制逻辑接入时统一建立。

项目总设计中曾预设SensorTask为100 ms周期，并每10次读取一次DHT11。该预设面向DHT11与MQ-2同时接入后的组合任务；M3A只有DHT11，因此本设计以2秒任务周期为准。M3B接入MQ-2时再将快速ADC采样与低频DHT11读取拆分或组合，不在M3A提前实现。

## 4. 硬件连接

```text
DHT11 VCC  → STM32 3.3V
DHT11 DATA → STM32 PD0
DHT11 GND  → STM32 GND
```

三针DHT11模块通常带板载数据上拉电阻，因此M3A不增加外部上拉。接线前必须根据实物丝印确认VCC、DATA和GND顺序，不能仅根据针脚位置猜测。

模块使用3.3V而不是5V供电，避免模块板载上拉把DATA拉到5V。DHT11读取时不得连接MQ-2 AO或DO到STM32。

## 5. 软件组件

新增DHT11 BSP文件：

```text
firmware/SmartHood/BSP/Inc/bsp_dht11.h
firmware/SmartHood/BSP/Src/bsp_dht11.c
```

驱动向应用层提供一次完整读取接口，并返回明确状态：

```text
DHT11_STATUS_OK
DHT11_STATUS_TIMEOUT
DHT11_STATUS_CHECKSUM_ERROR
```

有效结果使用扩大10倍的整数保存：

```text
temperature_x10 = 260  → 26.0 °C
humidity_x10    = 580  → 58.0 %RH
```

这种表示保留一位小数，不依赖浮点运算或浮点格式化。驱动内部接收并校验完整5字节原始帧；只有状态为OK时才更新调用者提供的结果，失败帧不得覆盖上一次有效数据。

## 6. 单总线时序

一次读取按以下顺序执行：

1. 将PD0配置为开漏输出并拉低约18 ms，发出主机启动信号。
2. 释放总线并将PD0切换为输入。
3. 等待DHT11响应低电平和响应高电平。
4. 读取40位数据：每一位先等待固定低电平，再测量高电平宽度。
5. 根据高电平宽度区分0和1，组合为5个字节。
6. 校验`(byte0 + byte1 + byte2 + byte3) & 0xFF`是否等于`byte4`。
7. 无论成功或失败，都将PD0恢复为输入状态并恢复进入读取前的中断状态。

18 ms启动低电平阶段允许正常任务调度和中断。进入传感器响应与40位采集阶段后，为避免SysTick或其他中断拉长短脉冲测量，允许在约4 ms内短暂屏蔽中断。代码必须保存进入前的中断状态，并通过统一清理路径恢复，禁止在超时分支提前返回而遗留关中断状态。

每次等待电平变化都必须设置微秒级超时，不允许使用无上限的`while`循环。驱动采集期间不调用串口日志、屏幕绘制或FreeRTOS延时。

## 7. 数据流与日志

```text
SensorTask每2秒唤醒
        ↓
BSP_DHT11_Read()
        ↓
状态与有效数据
        ↓
SensorTask格式化USART1日志
        ↓
延迟至下一读取周期
```

成功日志格式：

```text
DHT11 temp=26.0C humidity=58.0% status=OK
```

失败日志格式：

```text
DHT11 status=TIMEOUT
DHT11 status=CHECKSUM_ERROR
```

断线期间`SensorTask`每2秒重新尝试，不进行永久故障锁定。传感器重新接入后，下一次成功读取直接恢复OK日志。

## 8. 多任务串口保护

M3A完成后，`App_DefaultTask`和`SensorTask`都可能调用`DebugLog_Printf()`。为防止USART1发送交叉、HAL忙状态或日志丢失，日志模块增加互斥锁：

1. 在FreeRTOS任务创建前初始化日志互斥锁。
2. `DebugLog_Printf()`在格式化与发送前获取互斥锁。
3. 发送完成或失败后释放互斥锁。
4. 不在DHT11微秒采集区间内调用日志接口。

互斥锁只保护日志输出，不用于DHT11时序采集。

## 9. 错误处理

- 任意响应边沿或数据位等待超时：返回`DHT11_STATUS_TIMEOUT`。
- 数据校验失败：返回`DHT11_STATUS_CHECKSUM_ERROR`。
- 错误读取不更新有效数据。
- 所有错误出口恢复PD0输入模式和原中断状态。
- 错误不会终止或挂起`SensorTask`；下一个2秒周期继续读取。
- DHT11错误不影响TFT、PA0、PA1和默认任务心跳。

## 10. 验收标准

### 10.1 构建检查

- Keil全量编译为0 Error(s)、0 Warning(s)。
- 构建日志确认TIM5、`bsp_dht11.c`和SensorTask代码参与编译或链接。

### 10.2 未连接启动

- DHT11未连接时，每约2秒输出一次`DHT11 status=TIMEOUT`。
- 默认任务心跳持续递增，PA0、PA1和TFT原有功能正常。
- 系统不死机、不长期关中断、不重复复位。

### 10.3 正常采集

- 接线正确后，在2秒内自动输出有效温湿度。
- 稳定接线条件下连续获得至少10次有效读数。
- 日志中的温湿度格式正确，校验失败数据不作为有效值输出。

### 10.4 变化响应

- 对传感器缓慢哈气后，湿度读数出现可观察变化。
- 测试时避免让水汽直接凝结在模块上。

### 10.5 断线与自动恢复

- 运行中断开DATA线后出现TIMEOUT，其他任务继续运行。
- 重新连接DATA线后不按RST，后续采样周期自动恢复OK日志。

### 10.6 回归检查

- TFT保持M2最终测试画面，无异常刷新或白屏。
- PA0松开为0、按下为1。
- PA1继续每秒翻转。
- USART1心跳和DHT11日志无乱码、无明显交叉或丢失。

## 11. 不在M3A范围内

- MQ-2供电、ADC接线、滤波、预热或标定。
- 在TFT上显示实时温湿度。
- LVGL移植。
- 完整`SystemState`、传感器融合或自动调速。
- DHT11中断捕获、DMA或复杂异步状态机。
